## 🧠 핵심 정리

### 1️⃣ JPQL Projection

Projection은 조회 결과를 어떤 형태로 반환할지 지정하는 기능이다.

JPQL은 엔티티뿐만 아니라 특정 컬럼이나 DTO 형태로도 조회할 수 있다.

---

### 2️⃣ 엔티티 프로젝션(Entity Projection)

엔티티 자체를 조회하는 방식이다.

```java
String jpql = "SELECT m FROM Section03Menu m";

List<Menu> menuList =
        entityManager.createQuery(jpql, Menu.class)
                     .getResultList();
```

조회된 엔티티는 영속성 컨텍스트에 의해 관리된다.

```java
menuList.get(0).setMenuName("맛있는 삼겹살");
```

엔티티의 값을 변경하면 변경 감지(Dirty Checking)가 동작하여 트랜잭션 종료 시 데이터베이스에 반영된다.

```java
@Transactional
public List<Menu> singleEntityProjection() {
    List<Menu> menuList = projectionRepository.singleEntityProjection();
    menuList.get(0).setMenuName("맛있는 삼겹살");
    return menuList;
}
```

---

### 3️⃣ 스칼라 타입 프로젝션(Scalar Projection)

특정 컬럼만 조회하는 방식이다.

```java
String jpql = "SELECT c.categoryCode, c.categoryName FROM Section03Category c";
```

조회 결과는 여러 컬럼이므로 `Object[]` 형태로 반환된다.

```java
List<Object[]> categoryList =
        entityManager.createQuery(jpql).getResultList();
```

예시

```java
for(Object[] row : categoryList){
    System.out.println(row[0] + " " + row[1]);
}
```

---

### 4️⃣ DTO 프로젝션(new 명령어)

조회 결과를 DTO 객체로 바로 변환할 수 있다.

```java
String jpql =
        "SELECT new com.ohgiraffers.jpql.section03.projection.CategoryInfo(" +
        "c.categoryCode, c.categoryName) " +
        "FROM Section03Category c";
```

```java
List<CategoryInfo> categoryInfoList =
        entityManager.createQuery(jpql, CategoryInfo.class)
                     .getResultList();
```

장점

* Object[] 사용 불필요
* 타입 안정성 확보
* 가독성 향상

---

### 5️⃣ JPQL 페이징 처리

대량의 데이터를 한 번에 조회하지 않고 필요한 데이터만 조회하는 기능이다.

JPA는 Paging API를 제공한다.

```java
String jpql = "SELECT m FROM Section04Menu m ORDER BY m.menuCode DESC";
```

```java
TypedQuery<Menu> query =
        entityManager.createQuery(jpql, Menu.class)
                     .setFirstResult(offset)
                     .setMaxResults(limit);
```

---

#### setFirstResult()

조회 시작 위치를 지정한다.

```java
.setFirstResult(10)
```

11번째 데이터부터 조회한다.

---

#### setMaxResults()

조회할 데이터 개수를 지정한다.

```java
.setMaxResults(5)
```

최대 5건 조회

---

### 6️⃣ JPQL 집계 함수(Group Function)

JPQL에서도 SQL과 동일하게 집계 함수를 사용할 수 있다.

---

#### COUNT

특정 카테고리에 속한 메뉴 개수 조회

```java
String jpql =
        "SELECT COUNT(m.menuCode) " +
        "FROM Section05Menu m " +
        "WHERE m.categoryCode = :categoryCode";
```

```java
long countMenu =
        entityManager.createQuery(jpql, Long.class)
                     .setParameter("categoryCode", categoryCode)
                     .getSingleResult();
```

---

#### SUM

특정 카테고리 메뉴 가격 합계 조회

```java
String jpql =
        "SELECT SUM(m.menuPrice) " +
        "FROM Section05Menu m " +
        "WHERE m.categoryCode = :categoryCode";
```

```java
Long sumOfMenu =
        entityManager.createQuery(jpql, Long.class)
                     .setParameter("categoryCode", categoryCode)
                     .getSingleResult();
```

---

### 7️⃣ COUNT와 다른 집계 함수의 차이

COUNT는 조회 결과가 없어도 0을 반환한다.

```java
COUNT(...) → 0
```

반면 SUM, AVG, MAX, MIN은 조회 결과가 없으면 null을 반환한다.

```java
SUM(...) → null
```

따라서 null 처리가 필요하다.

---

### 8️⃣ GROUP BY와 HAVING

카테고리별 메뉴 가격 합계를 조회하였다.

```java
String jpql =
        "SELECT m.categoryCode, SUM(m.menuPrice) " +
        "FROM Section05Menu m " +
        "GROUP BY m.categoryCode";
```

---

#### HAVING 사용

합계 금액이 특정 값 이상인 카테고리만 조회

```java
String jpql =
        "SELECT m.categoryCode, SUM(m.menuPrice) " +
        "FROM Section05Menu m " +
        "GROUP BY m.categoryCode " +
        "HAVING SUM(m.menuPrice) >= :minPrice";
```

```java
List<Object[]> result =
        entityManager.createQuery(jpql)
                     .setParameter("minPrice", minPrice)
                     .getResultList();
```
