### 🧠 핵심 정리
**1️⃣ Spring Data JPA와 JpaRepository**
Spring Data JPA는 JPA 기반의 Repository 추상화 레이어이다.
* `EntityManager`를 직접 다루지 않고 **인터페이스 선언**만으로 데이터베이스 제어가 가능하다.
* `JpaRepository<엔티티, PK타입>`을 상속하면 `findById()`, `findAll()`, `save()`, `delete()` 등 기본 CRUD 메소드가 자동으로 제공된다.

**2️⃣ 쿼리 메소드 (Query Method)**
메소드 이름 규칙에 따라 JPA가 자동으로 JPQL을 생성해 준다.
* `findBy`, `GreaterThan`, `OrderBy...Desc`, `And/Or` 등의 키워드를 조합하여 조건식과 정렬을 쉽게 구현할 수 있다.
* `Pageable` 파라미터를 추가하면 동적 정렬 및 페이징 처리도 간편하게 지원된다.

**3️⃣ 페이징 (Pagination)**
* **Repository:** `Pageable` 파라미터를 넘겨주면 `Page<T>` 타입으로 반환되며, 여기에는 데이터뿐만 아니라 총 개수, 총 페이지 수 등 메타정보가 포함된다.
* **Controller:** `@PageableDefault`를 사용해 클라이언트가 파라미터를 보내지 않을 때의 기본 페이지 사이즈와 정렬 기준을 설정할 수 있다.
* **Service:** `Page.map()`을 사용하면 페이지 메타정보를 유지한 채로 엔티티를 DTO로 손쉽게 변환할 수 있다.

**4️⃣ DTO 분리와 ModelMapper**
엔티티의 직접 노출을 막기 위해 클라이언트 입력용(Request)과 응답 반환용(Response) DTO를 분리해야 한다.
* 엔티티와 DTO 간의 변환을 위해 `ModelMapper`를 활용한다.
* Getter가 없는 엔티티 구조에서 매핑 실패를 방지하려면, ModelMapper 설정 시 `setFieldAccessLevel(AccessLevel.PRIVATE)` 옵션을 주어 private 필드에 직접 접근하게 해야 한다.

**5️⃣ 안전한 엔티티 설계 (Lombok + Builder)**
* `@NoArgsConstructor(access = AccessLevel.PROTECTED)`: JPA 스펙을 충족하면서 외부의 무분별한 기본 객체 생성을 차단한다.
* `@Builder` 패턴을 사용하여 객체 생성 시 가독성과 안전성을 높인다.
* 무분별한 Setter 사용을 지양하고, 대신 `modifyMenuPrice()`처럼 의도가 명확한 수정 메소드를 만들어 캡슐화한다.

### ⚙️ 적용
* **JpaRepository 상속 및 쿼리 메소드 활용**
  * 반복적인 CRUD 및 조회 쿼리 작성을 줄이고, 복잡한 검색 조건도 메소드명 규칙으로 해결
* **Pageable 기반 동적 페이징 처리**
  * 대량의 데이터 목록(메뉴, 게시판 등) 반환 시 서버와 DB 부하를 줄이기 위해 API에 페이징 적용
* **API 응답 및 요청 규격화**
  * 비즈니스 로직(Service)에서 DTO 분리 및 ModelMapper 변환을 철저히 하여, 화면 요구사항 변경이 엔티티에 영향을 주지 않도록 결합도 낮추기
