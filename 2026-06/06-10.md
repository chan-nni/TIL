## 🧠 핵심 정리

### 1️⃣ 엔티티 생명주기(Entity Life Cycle)

JPA에서 엔티티는 상태에 따라 관리 방식이 달라진다.

**엔티티 상태**

| 상태             | 설명                        |
| -------------- | ------------------------- |
| 비영속(Transient) | 영속성 컨텍스트와 관계없는 순수 객체      |
| 영속(Managed)    | 영속성 컨텍스트가 관리하는 객체         |
| 준영속(Detached)  | 영속성 컨텍스트가 더 이상 관리하지 않는 객체 |
| 삭제(Removed)    | 삭제가 예약된 객체                |

```java
Menu foundMenu = entityManager.find(Menu.class, menuCode);

Menu newMenu = new Menu(
        foundMenu.getMenuCode(),
        foundMenu.getMenuName(),
        foundMenu.getMenuPrice(),
        foundMenu.getCategoryCode(),
        foundMenu.getOrderableStatus()
);
```

위 코드에서 `foundMenu`는 영속 상태이고, `newMenu`는 단순히 생성한 객체이므로 비영속 상태이다.

```java
entityManager.contains(foundMenu); // true
entityManager.contains(newMenu);   // false
```

### 2️⃣ 영속성 컨텍스트의 1차 캐시

같은 `EntityManager`에서 동일한 PK를 조회하면 1차 캐시를 사용한다.

```java
Menu menu1 = entityManager.find(Menu.class, 3);
Menu menu2 = entityManager.find(Menu.class, 3);

assertEquals(menu1, menu2);
```

같은 객체를 반환하기 때문에 참조값도 동일하다.

반면 다른 `EntityManager`에서 조회하면 서로 다른 객체가 생성된다.

```java
Menu menu1 = lifeCycle.findMenuByMenuCode(3);
Menu menu2 = lifeCycle.findMenuByMenuCode(3);

assertNotEquals(menu1, menu2);
```

---

### 3️⃣ detach()를 이용한 준영속 상태

`detach()`는 특정 엔티티만 영속성 컨텍스트에서 분리한다.

```java
Menu foundMenu = entityManager.find(Menu.class, menuCode);

entityManager.detach(foundMenu);

foundMenu.setMenuPrice(1000);
entityManager.flush();
```

준영속 상태가 된 객체는 변경 감지(Dirty Checking)가 동작하지 않는다.

따라서 DB에는 수정 내용이 반영되지 않는다.

---

### 4️⃣ merge()를 이용한 재영속화

준영속 상태의 엔티티를 다시 영속 상태로 만들 수 있다.

```java
entityManager.detach(foundMenu);

foundMenu.setMenuPrice(1000);

entityManager.merge(foundMenu);

entityManager.flush();
```

`merge()`를 수행하면 변경 내용이 영속성 컨텍스트에 반영되고 DB 업데이트가 가능해진다.

---

### 5️⃣ clear()와 close()

#### clear()

영속성 컨텍스트 내부의 모든 엔티티를 준영속 상태로 만든다.

```java
entityManager.clear();
```

이후 다시 조회하면 새로운 객체가 반환된다.

```java
Menu expectedMenu = entityManager.find(Menu.class, menuCode);

assertNotEquals(foundMenu, expectedMenu);
```

---

#### close()

영속성 컨텍스트 자체를 종료한다.

```java
entityManager.close();
```

더 이상 해당 `EntityManager`를 사용할 수 없다.

---

### 6️⃣ JPA 엔티티 매핑

엔티티는 데이터베이스 테이블과 매핑된다.

```java
@Entity(name = "Section03Menu")
@Table(name = "tbl_menu")
public class Menu {
}
```

#### 주요 어노테이션

* `@Entity` : 엔티티 클래스 지정
* `@Table` : 매핑할 테이블 지정
* `@Id` : 기본키 지정
* `@GeneratedValue` : PK 자동 생성
* `@Column` : 컬럼 매핑

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
@Column(name = "menu_code")
private int menuCode;
```

---

### 7️⃣ @Transient

데이터베이스 컬럼과 매핑하지 않는 필드에 사용한다.

```java
@Transient
private String phone;
```

객체 내부 로직에서는 사용할 수 있지만 DB에는 저장되지 않는다.

---

### 8️⃣ Enum 매핑

Enum 타입은 `@Enumerated`를 사용하여 매핑한다.

```java
public enum MemberRole {
    ROLE_MEMBER,
    ROLE_ADMIN
}
```

```java
@Enumerated(EnumType.STRING)
@Column(name = "member_role")
private MemberRole memberRole;
```

#### EnumType 종류

**ORDINAL**

```java
@Enumerated(EnumType.ORDINAL)
```

* 숫자로 저장
* 저장 공간이 작음
* Enum 순서 변경 시 문제 발생 가능

---

**STRING**

```java
@Enumerated(EnumType.STRING)
```

* 문자열로 저장
* Enum 추가 및 순서 변경에 안전

---

### 9️⃣ Hibernate DDL 자동 생성

`application.yml` 설정을 통해 테이블을 자동 생성할 수 있다.

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: create
```

주요 옵션

| 옵션          | 설명          |
| ----------- | ----------- |
| create      | 실행 시 테이블 생성 |
| update      | 변경 사항 반영    |
| validate    | 엔티티와 테이블 검증 |
| create-drop | 종료 시 테이블 삭제 |

## ⚙️ 적용

### 엔티티 생명주기 실습

* 비영속, 영속, 준영속 상태를 테스트 코드로 확인
* `detach()`와 `merge()` 동작 방식 학습

### 영속성 컨텍스트 이해

* 동일한 EntityManager에서는 1차 캐시가 동작함을 확인
* 다른 EntityManager 사용 시 새로운 객체가 생성됨을 확인

### JPA 매핑 실습

* `@Entity`, `@Table`, `@Column` 등을 이용한 엔티티 매핑 구현
* `@GeneratedValue`를 이용한 PK 자동 생성 적용

### Enum 및 컬럼 매핑

* `@Enumerated(EnumType.STRING)`을 활용하여 Enum 데이터 저장
* `@Transient`를 이용하여 DB에 저장하지 않는 필드 구성
