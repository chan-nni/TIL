## 🧠 핵심 정리

### 1️⃣ 보조 스트림 (Filter Stream)

기본 스트림(Node Stream)에 추가 기능을 부여하는 '필터' 같은 존재이다.

* **구조와 특징**
* 실제 데이터 소스(파일, 네트워크)에 직접 접근하지 못하며, 반드시 기본 스트림을 감싸서 사용한다.
* 여러 개의 보조 스트림을 겹겹이 감싸서 기능을 중첩시킬 수 있다. (데코레이터 패턴)

### 2️⃣ BufferedWriter & BufferedReader (성능 향상)

데이터를 한 글자씩 옮기지 않고, 메모리 버퍼(Buffer)에 모아두었다가 한꺼번에 처리한다.

* **입출력 효율화**
* `BufferedWriter`: 데이터를 쓰기 작업 시 잦은 디스크 접근을 줄여 성능을 비약적으로 향상시킨다.
* `BufferedReader`: `readLine()` 메서드를 통해 텍스트를 한 줄씩(`String`) 읽어오기 매우 편리하다.

* **자원 관리**
* `flush()`: 버퍼에 남은 데이터를 강제로 목적지에 밀어 넣는다.
* `try-with-resources`: 사용 후 자동으로 `close()`를 호출하여 자원 누수를 방지한다.

### 3️⃣ InputStreamReader (형변환 보조 스트림)

바이트 기반 스트림을 문자 기반 스트림으로 연결해 주는 '다리' 역할을 한다.

* **사용 목적**
* 1byte 단위로 입력받는 바이트 스트림(예: `System.in`)을 한글 깨짐 없이 처리하기 위해 2byte(char) 기반의 문자 스트림으로 변환한다.

* **조합 방식**
* `BufferedReader br = new BufferedReader(new InputStreamReader(System.in));`
* 키보드(바이트) → 문자 변환(Reader) → 버퍼링(ReadLine 가능) 순으로 기능을 확장한다.

## ⚙️ 적용

* **버퍼 기반 입출력**: `FileWriter` 단독 사용보다 `BufferedWriter`로 감싸서 대량의 데이터 처리 성능 최적화
* **사용자 입력 처리**: `Scanner` 대신 `BufferedReader`와 `InputStreamReader`를 조합하여 속도가 빠르고 효율적인 한 줄 단위 입력 로직 구현
